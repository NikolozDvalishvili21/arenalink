# ArenaLink: Product Backlog

პროექტის აღწერა და stakeholder-ები: [README](../README.md)

## User story-ები

სულ 18 story. თითოეულს აქვს MoSCoW კატეგორია და ქულა (Fibonacci). იგივე ბარათებია GitHub Projects დაფაზე.

### Must have

**US-01 · რეგისტრაცია და შესვლა (3)**

As a მოთამაშე, I want ელფოსტით და პაროლით რეგისტრაცია და შესვლა, so that ჩემი სახელით ვიმოქმედო.

- Given ახალი ელფოსტა და 8+ სიმბოლოიანი პაროლი, When ფორმას ვაგზავნი, Then ანგარიში იქმნება და ავტომატურად შევდივარ.
- Given ელფოსტა უკვე დაკავებულია, When რეგისტრაციას ვცდილობ, Then ვხედავ შეცდომას.

**US-02 · ტურნირის შექმნა (5)**

As an ორგანიზატორი, I want ტურნირის შექმნა (სახელი, თამაში, თარიღი, გუნდების რაოდენობა, შესატანი), so that გუნდებმა რეგისტრაცია დაიწყონ.

- Given ორგანიზატორი ვარ, When ველებს ვავსებ და ვაქვეყნებ, Then ტურნირი სიაში ჩნდება სტატუსით „რეგისტრაცია ღიაა“.
- Given გუნდების რაოდენობა არ არის 4, 8, 16 ან 32, When ვაქვეყნებ, Then ვხედავ შეცდომას.

**US-03 · გუნდის შექმნა (3)**

As a მოთამაშე, I want გუნდის შექმნა სახელით და წევრების ნიკნეიმებით, so that გუნდით დავრეგისტრირდე ტურნირზე.

- Given შესული ვარ, When გუნდის სახელს და წევრების ნიკნეიმებს ვწერ, Then გუნდი იქმნება და მე ვარ კაპიტანი.
- Given ასეთი სახელით გუნდი უკვე არსებობს, When გუნდს ვქმნი, Then ვხედავ შეცდომას.

წევრებს საიტზე ანგარიში არ სჭირდებათ, შედეგს ისედაც კაპიტანი აგზავნის. 1 vs 1 თამაშებში (მაგ. EA FC) გუნდი მხოლოდ ერთი მოთამაშისგან შედგება.

**US-04 · ტურნირზე რეგისტრაცია და გადახდა (8)**

As a კაპიტანი, I want გუნდის რეგისტრაცია და შესატანის გადახდა, so that ტურნირზე ადგილი მქონდეს.

- Given თავისუფალი ადგილია, When გადახდა წარმატებულია, Then გუნდი „დადასტურებულია“.
- Given ბოლო ადგილზე ორი გუნდი ერთად იწყებს გადახდას, When ორივე ადგილს იკავებს, Then ადგილი 10 წუთით პირველს ენიჭება, მეორე კი ხედავს „ადგილები შეივსო“.

**US-05 · ცხრილის გენერაცია (8)**

As an ორგანიზატორი, I want ცხრილის ავტომატური აგება, so that ხელით არ შევადგინო.

- Given ყველა ადგილი შევსებულია, When ვაჭერ „ცხრილის გენერაციას“, Then იქმნება single elimination ცხრილი შემთხვევითი წყვილებით.
- Given გუნდები აკლია, When გენერაციას ვცდილობ, Then სისტემა მეუბნება, რამდენი გუნდი აკლია.

**US-06 · შედეგის გაგზავნა და დადასტურება (5)**

As a კაპიტანი, I want შედეგის გაგზავნა და მეტოქის დადასტურება, so that გამარჯვებული შემდეგ მატჩში გადავიდეს.

- Given მატჩი დასრულდა, When ერთი კაპიტანი ანგარიშს აგზავნის, Then მეორე კაპიტანი ხედავს ღილაკებს „ვადასტურებ“ და „ვასაჩივრებ“.
- Given მეორე კაპიტანმა დაადასტურა, When დადასტურება სრულდება, Then მატჩი იხურება და გამარჯვებული შემდეგ მატჩში გადადის.
- Given მეორე კაპიტანმა გაასაჩივრა, When მიზეზს წერს, Then მატჩი „სადავოა“ და ორგანიზატორთან ჩანს.
- Given შედეგი გაგზავნილია, When 10 წუთი გადის პასუხის გარეშე, Then შედეგი ავტომატურად დასტურდება.

**US-07 · ცხრილის ნახვა (3)**

As a მაყურებელი, I want ცხრილის ნახვა ანგარიშის გარეშე, so that ვიცოდე, ვინ ვის ეთამაშება.

- Given ცხრილი შექმნილია, When საჯარო ბმულს ვხსნი, Then ვხედავ ყველა მატჩს და ანგარიშს.

### Should have

**US-08a · ცხრილის ავტომატური განახლება (5)**

As a მაყურებელი, I want ცხრილი თავისით განახლდეს, so that გვერდი არ გადავტვირთო.

- Given ცხრილის გვერდი ღიაა, When შედეგი დასტურდება, Then ცვლილება 3 წამში ჩანს.

**US-08b · „LIVE“ ნიშანი (3)**

As a მაყურებელი, I want ვიცოდე, რომელი მატჩი მიდის ახლა, so that სწორ მატჩს ვუყურო.

- Given მატჩი დაიწყო, When ცხრილს ვხსნი, Then მატჩზე ჩანს „LIVE“.

**US-09 · შეხსენება მატჩამდე (3)**

As a მოთამაშე, I want შეხსენება მატჩამდე, so that არ დავაგვიანო.

- Given მატჩამდე 15 წუთია, When ეს დრო დგება, Then ელფოსტით ვიღებ შეხსენებას.

**US-10 · ორგანიზატორის დამატება (3)**

As an ადმინისტრატორი, I want მომხმარებლისთვის ორგანიზატორის როლის მინიჭება, so that ტურნირები მხოლოდ სანდო ადამიანებმა შექმნან.

- Given მომხმარებელი რეგისტრირებულია, When ადმინის პანელში ორგანიზატორის როლს ვანიჭებ, Then მას ტურნირის შექმნა შეუძლია.
- Given მომხმარებელი ორგანიზატორი არ არის, When ტურნირის შექმნას ცდილობს, Then სისტემა არ აძლევს უფლებას.

**US-11 · სადავო შედეგის გადაწყვეტა (5)**

As an ორგანიზატორი, I want სადავო მატჩის განხილვა, so that ტურნირი არ გაჩერდეს.

- Given მატჩი სადავოა, When ვხედავ მიზეზს და მატჩის ჩანაწერს, Then ვირჩევ: დადასტურება, შეცვლა ან გადათამაშება.

As a მაყურებელი, I want ვიცოდე, როცა ინტერნეტი გამეთიშა, so that ძველი ცხრილი ახალი არ მეგონოს.

**US-16 · თანაგუნდელების მოწვევა (3)**

As a კაპიტანი, I want თანაგუნდელების მოწვევა საიტის ანგარიშით, so that თითოეულს თავისი პროფილი ჰქონდეს.

- Given კაპიტანი ვარ, When მოთამაშე მოწვევას იღებს, Then ის გუნდის წევრებში ანგარიშით ჩნდება.

**US-12 · გადახდების CSV (3)**

- Given რეგისტრაციები არსებობს, When ვაჭერ „CSV გადმოწერას“, Then ფაილში არის გუნდი, თანხა და თარიღი.

**US-13 · სპონსორის ლოგო (2)**

- Given ორგანიზატორმა ლოგო დაამატა, When ტურნირის გვერდს ვხსნი, Then ლოგო ზემოთ ჩანს.

## არაფუნქციური მოთხოვნები

- **NFR-01, სისწრაფე.** ცხრილის გვერდი უნდა იტვირთებოდეს <=2 წამში. მოწმდება Lighthouse-ით.
- **NFR-02, დატვირთვა.** სისტემა უძლებს 500 ერთდროულ მაყურებელს, შეცდომები 1%-ზე ნაკლებია. მოწმდება k6-ით.
- **NFR-03, განახლება.** შედეგის დადასტურებიდან ცხრილის განახლებამდე მაქსიმუმ 3 წამი.
- **NFR-04, ხელმისაწვდომობა.** ტურნირის დროს გათიშვა მაქსიმუმ 5 წუთი. ვაკვირდები UptimeRobot-ით.
- **NFR-05, სიზუსტე.** ბოლო ადგილზე 50 ერთდროული რეგისტრაციიდან მხოლოდ 1 გადის.

## Definition of Done

Story დასრულებულია, როცა:

- კოდი pull request-ით შევიდა `main`-ში.
- ტესტები დაწერილია და გადის, CI მწვანეა.
- ყველა Given/When/Then შემოწმებულია.
- თუ story NFR-ს ეხება, ისიც შემოწმებულია.
- ბარათი დაფაზე „Done“ სვეტშია.

## MVP

MVP = ყველა Must story: US-01 – US-07, **35 ქულა**.

MVP მზადაა, როცა: ორგანიზატორი ქმნის 8-გუნდიან ტურნირს, 8 გუნდი რეგისტრირდება და იხდის (სატესტო mock გადახდით), იქმნება ცხრილი, გუნდები ფინალამდე აგზავნიან შედეგებს, მაყურებელი კი ცხრილს საჯარო ბმულზე ხედავს.

MVP-ში სადავო მატჩს ორგანიზატორი ხელით აგვარებს. ადმინის პანელამდე (US-10) ორგანიზატორის როლს ბაზაში ხელით ვანიჭებ.
