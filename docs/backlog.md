# ArenaLink: Product Backlog

პროექტის აღწერა და stakeholder-ები: [README](../README.md)

## User story-ები

სულ 17 story-ა. თითოეულს აქვს MoSCoW კატეგორია და ქულა (Fibonacci). ეს იგივე ბარათებია, რაც GitHub Projects დაფაზეა.

### Must have

**US-01 · რეგისტრაცია და შესვლა (3)**

As a მოთამაშე, I want ელფოსტითა და პაროლით ანგარიშის შექმნა და შესვლა, so that გუნდსა და ტურნირზე ჩემი სახელით ვიმოქმედო.

- Given უნიკალური ელფოსტითა და მინიმუმ 8-სიმბოლოიანი პაროლით ვავსებ ფორმას, When ვაგზავნი, Then ანგარიში იქმნება და სისტემაში ავტომატურად შევდივარ.
- Given ელფოსტა უკვე დაკავებულია, When ვცდილობ რეგისტრაციას, Then ვხედავ შეცდომას და ახალი ანგარიში არ იქმნება.

**US-02 · ტურნირის შექმნა (5)**

As an ორგანიზატორი, I want ტურნირის შექმნა (სახელი, თამაში, თარიღი, გუნდების რაოდენობა, შესატანი), so that გუნდებმა რეგისტრაცია დაიწყონ.

- Given ავტორიზებული ორგანიზატორი ვარ, When სავალდებულო ველებს ვავსებ და ვაქვეყნებ, Then ტურნირი საჯარო სიაში ჩნდება სტატუსით „რეგისტრაცია ღიაა“.
- Given გუნდების რაოდენობა არ არის 4, 8, 16 ან 32, When ვცდილობ გამოქვეყნებას, Then სისტემა შეცდომას მაჩვენებს და ტურნირი არ ქვეყნდება.

**US-03 · გუნდის შექმნა და წევრების მოწვევა (5)**

As a მოთამაშე, I want გუნდის შექმნა და თანაგუნდელების მოწვევა, so that ტურნირზე ერთად დავრეგისტრირდეთ.

- Given ავტორიზებული ვარ, When ვქმნი გუნდს უნიკალური სახელით, Then ვხდები გუნდის კაპიტანი.
- Given გუნდის კაპიტანი ვარ, When მოთამაშეს ვუგზავნი მოწვევას ელფოსტაზე და ის იღებს მას, Then ის გუნდის წევრთა სიაში ჩნდება.

**US-04 · ტურნირზე რეგისტრაცია და გადახდა (8)**

As a გუნდის კაპიტანი, I want ჩემი გუნდის დარეგისტრირება ტურნირზე და შესატანის ონლაინ გადახდა, so that ადგილი დამიმტკიცდეს.

- Given ტურნირზე თავისუფალი ადგილია, When გადახდა წარმატებით სრულდება, Then გუნდი მონაწილეთა სიაში ჩნდება სტატუსით „დადასტურებული“.
- Given ბოლო თავისუფალ ადგილზე ორი გუნდი ერთდროულად იწყებს გადახდას, When ორივე ცდილობს ადგილის დაკავებას, Then ადგილი 10 წუთით პირველს ენიჭება, მეორე კი ხედავს შეტყობინებას „ადგილები შეივსო“.

**US-05 · ბრეკეტის ავტომატური გენერაცია (8)**

As an ორგანიზატორი, I want რეგისტრაციის დახურვისას ბრეკეტის ავტომატური აგება, so that ცხრილის ხელით შედგენა აღარ მჭირდებოდეს.

- Given რეგისტრაცია დახურულია და დადასტურებულ გუნდთა რაოდენობა ტურნირის ლიმიტის ტოლია, When ვაჭერ „ბრეკეტის გენერაციას“, Then სისტემა ქმნის single elimination ბრეკეტს შემთხვევითი განაწილებით და ყველა მატჩს აქვს სტატუსი „დაგეგმილი“.
- Given დადასტურებულ გუნდთა რაოდენობა ლიმიტზე ნაკლებია, When ვცდილობ გენერაციას, Then სისტემა მოქმედებას ბლოკავს და მიჩვენებს, რამდენი გუნდი აკლია.

**US-06 · შედეგის გაგზავნა და დადასტურება (5)**

As a გუნდის კაპიტანი, I want მატჩის შედეგის გაგზავნა და მეტოქის მიერ დადასტურება, so that გამარჯვებული შემდეგ ეტაპზე გადავიდეს.

- Given ჩემი მატჩი დასრულდა, When ვაგზავნი ანგარიშს და მეტოქე კაპიტანი ადასტურებს, Then მატჩი იხურება და გამარჯვებული ავტომატურად გადადის შემდეგ მატჩში.
- Given მეტოქე კაპიტანი ანგარიშს არ ეთანხმება, When უარყოფს შედეგს, Then მატჩი იღებს სტატუსს „სადავო“ და ორგანიზატორის პანელში ჩანს.

**US-07 · ბრეკეტის ნახვა (3)**

As a მაყურებელი, I want ტურნირის ბრეკეტისა და შედეგების ნახვა რეგისტრაციის გარეშე, so that ვიცოდე, ვინ ვის ეთამაშება.

- Given ტურნირის ბრეკეტი გენერირებულია, When საჯარო ბმულს ვხსნი, Then ავტორიზაციის გარეშე ვხედავ ყველა მატჩს, გუნდებს და დასრულებული მატჩების ანგარიშს.

**US-09 · შეტყობინება მატჩამდე (3)**

**US-10 · ორგანიზატორის დამტკიცება (3)**

As an ადმინისტრატორი, I want ახალი ორგანიზატორის დამტკიცება ან უარყოფა, so that პლატფორმაზე თაღლითური ტურნირები არ გამოქვეყნდეს.

- Given ორგანიზატორის განაცხადი განხილვას ელოდება, When ვამტკიცებ, Then ორგანიზატორს ტურნირის შექმნის უფლება უჩნდება.
- Given ორგანიზატორი დაუმტკიცებელია, When ტურნირის გამოქვეყნებას ცდილობს, Then სისტემა მოქმედებას უკრძალავს.

**US-11 · სადავო შედეგის გადაწყვეტა (5)**

As an ორგანიზატორი, I want სადავო შედეგის დანახვა და საბოლოო გადაწყვეტილების მიღება, so that ტურნირი არ გაჭედოს.

- Given მატჩს აქვს სტატუსი „სადავო“, When გამარჯვებულს ვირჩევ და მიზეზს ვწერ, Then მატჩი იხურება და გადაწყვეტილება ორივე გუნდს ეჩვენება.

## არაფუნქციური მოთხოვნები

ყველა მოთხოვნა ტურნირის დღეს ეფუძნება, რადგან სწორედ მაშინ მოდის ყველაზე დიდი დატვირთვა: ყველა ერთდროულად უყურებს ბრეკეტს და ბევრი შედეგი ერთად დასტურდება.

- **NFR-01, სისწრაფე.** ბრეკეტის გვერდი 4G კავშირზე იტვირთება არაუმეტეს 2 წამში (მომხმარებლების 95%-ისთვის). ვამოწმებ Lighthouse-ით.
- **NFR-02, დატვირთვა.** სისტემა უძლებს 500 ერთდროულ მაყურებელს ერთ ტურნირზე და შეცდომიანი მოთხოვნების წილი 1%-ზე ნაკლებია. ვამოწმებ k6-ით: 500 ვირტუალური მომხმარებელი, 5 წუთი.
- **NFR-03, განახლების სიჩქარე.** შედეგის დადასტურებიდან ბრეკეტის განახლებამდე გადის არაუმეტეს 3 წამი. ვამოწმებ ავტომატური ტესტით.
- **NFR-04, ხელმისაწვდომობა.** ტურნირის მიმდინარეობისას გაუთვალისწინებელი შეფერხება არაუმეტეს 5 წუთია, დაგეგმილ განახლებებს კი ტურნირის დროს არ ვატარებ. ხელმისაწვდომობას UptimeRobot-ით ვაკვირდები.
- **NFR-05, მონაცემთა სისწორე.** ერთ თავისუფალ ადგილზე 50 ერთდროული რეგისტრაციიდან წარმატებით ერთი სრულდება და ადგილი არასდროს ორმაგდება. ვამოწმებ ინტეგრაციული ტესტით პარალელური მოთხოვნებით.

## პრიორიტეტები და შეფასება

Must have-ებია US-01 – US-07, ჯამში 37 ქულა. Should have: US-08a, US-08b, US-09, US-10, US-11, ჯამში 19 ქულა. Could have: US-08c, US-12, US-13, ჯამში 10 ქულა. Won't have: US-14 და US-15, ჯამში 21 ქულა, ამ სემესტრში არ კეთდება.

ქულები Fibonacci-ის სკალაზეა (1, 2, 3, 5, 8, 13) და მოცულობასთან ერთად სირთულესა და რისკსაც ითვალისწინებს. შეფასება მარტო მე გავაკეთე, ამიტომ საორიენტაციოდ US-02 (5 ქულა) ავიღე და დანარჩენი მასთან შევადარე. ამიტომ ყველაზე დიდი ქულა გადახდიან რეგისტრაციასა (US-04) და ბრეკეტის გენერაციას (US-05) აქვს, ორივე 8.

story დასრულებულია, როცა:
